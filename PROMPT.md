# Промпт: интерактивная страница «Айсберг курилки»

## Задача

Собрать одну интерактивную HTML-страницу — айсберг стикерпака «ку-ку курилка»
(`@TgEmodziBot`, пак `kykykyrilka_by_TgEmodziBot`). Страница рассчитана в первую
очередь на телефон: человек открывает её с мобильного, скроллит вниз, «погружается»
и видит, как стикеры распределены по слоям.

Работать нужно не с ощущением, а с данными: каждый стикер получает оценки по
нескольким шкалам, и позиция на айсберге вычисляется из этих оценок.

## Что уже решено (не менять без явного согласования)

- **Один айсберг**, не четыре отдельных страницы.
- **Вертикальная шкала:** вверху — добрые, внизу — токсичные. Ось «токсичность»
  направлена вниз, «доброта» — вверх. Чем глубже слой, тем жёстче стикер.
- **Несколько критериев на выбор:** токсичность, доброта, оригинальность.
  Переключатель меняет, по какой оценке раскладываются стикеры.
- **«От кого стикер»** — это не оценка, а атрибут: стикер выглядит как сообщение
  от персонажа, у него есть подпись/реплика. Показывается на карточке и работает
  как фильтр, а не как ось сортировки.
- **Стиль — мемный.** Допускаются шутки в подписях, но текст должен оставаться
  читаемым: никаких кислотных градиентов под мелким шрифтом.
- **Проект живёт в папке `aisberg-kurilki/`** внутри рабочего проекта.

## Данные: получены

Пак выгружен целиком через Telegram Bot API (`getStickerSet` + `getFile`).

- **120 стикеров**, тип `regular`, то есть статические WebP 512 px по ширине.
- Файлы лежат в `aisberg-kurilki/stickers/001.webp` … `120.webp`, нумерация
  совпадает с порядком в паке. Общий вес — 1.6 МБ.
- Метаданные пака — в `aisberg-kurilki/pack.json`.

**Формат стикера — фейковый скриншот переписки.** Это ключевая деталь: на
стикере 1–3 пузыря сообщений, у каждого своё содержимое:

- цветное имя отправителя («кира обнимай», «бюбють», «Правда»,
  «kalsarikännit ☾», «Калорья Молекульно́ва»);
- мелкая серая подпись-статус справа от имени («оборявт буллинг»,
  «мадам говно», «клофелинщица»);
- текст сообщения в пузыре;
- аватарка отправителя слева.

Отправители — выдуманные персонажи с абсурдными именами и статусами. Их состав
не фиксирован заранее: список собирается по факту просмотра всех 120 стикеров.

Токен бота в проект **не записывается** и в репозиторий не попадает.

### Схема `stickers.json`

```json
[
  {
    "id": "001",
    "file": "stickers/001.webp",
    "bubbles": 2,
    "senders": ["кира обнимай", "бюбють"],
    "statuses": ["оборявт буллинг", "мадам говно"],
    "text": "я не шучу, она прям очень много весит / грустно что я воняю",
    "kindness": 1,
    "toxicity": 9,
    "originality": 6,
    "tags": ["вес", "самооценка"]
  }
]
```

- `kindness`, `toxicity`, `originality` — целые от 1 до 10.
- `senders` — все имена отправителей на стикере, в порядке пузырей.
- `statuses` — подписи-статусы, по одной на отправителя.
- `text` — весь текст через ` / `, дословно, без исправления опечаток
  (опечатки здесь часть юмора).
- `tags` — 1–3 темы для будущего поиска.

### Объём работы по разметке

120 стикеров, каждый нужно посмотреть и оценить по трём шкалам. Разметка идёт
пачками по 10 стикеров на лист: лист собирается в HTML, снимается скриншотом,
стикеры читаются и переносятся в JSON. Это 12 листов. Транскрипция текста
делается только с реально просмотренных стикеров.

### Откуда брать оценки

Оценки ставит человек, глядя на стикеры. Правило: если оценка спорная — она
спорная, и это нормально; главное, чтобы одна и та же шкала применялась ко всем
стикерам одинаково. Нельзя «на глаз» выдумывать оценки для стикеров, которых
не видел.

## Структура страницы

1. **Экран-шапка.** Название «ку-ку курилка», короткая подпись в одну строку,
   кнопка «Открыть пак в Telegram».
2. **Залипающая панель критериев.** Три кнопки-переключателя: токсичность,
   доброта, оригинальность. Плюс фильтр по персонажу (чипы). Панель остаётся
   на экране при скролле, но не занимает больше 15% высоты.
3. **Айберг.** Вертикальная колонка слоёв: над водой → кромка → мелководье →
   глубина → дно. В каждом слое — стикеры, относящиеся к диапазону оценок.
   Слой подписан и имеет свой оттенок.
4. **Карточка стикера.** Тап по стикеру открывает нижнюю панель: крупное
   изображение, подпись, персонаж, оценки по трём шкалам, кнопка «В Telegram».
   Закрывается тапом мимо, свайпом вниз и клавишей Esc.

## Как ведёт себя взаимодействие

- Переключение критерия — стикеры переезжают в другие слои с короткой анимацией
  (150–250 мс). Без анимации при `prefers-reduced-motion: reduce`.
- Фильтр по персонажу — остальные стикеры приглушаются, но не исчезают,
  чтобы не терялась картина целого.
- Ссылка на конкретный стикер: состояние в адресной строке (`#id=07`), чтобы
  карточку можно было переслать.
- Счётчик: сколько стикеров в паке и сколько показано.

## Мобильные требования

- Базовая ширина — 360 px, проверять до 320 px включительно.
- Никакого горизонтального скролла ни при каких условиях.
- Тап-зоны не меньше 44×44 px.
- Шрифт основного текста не меньше 16 px, чтобы iOS не зумил при фокусе.
- Учитывать `env(safe-area-inset-bottom)` для нижней панели.
- Айберг рисуется CSS/SVG, а не картинкой: он должен тянуться под любую высоту
  экрана и не мылиться на Retina.
- Ориентация: портрет — основная; в альбомной не ломаться.

## Технические ограничения

- Один HTML-файл (стили и скрипт внутри) плюс папка `stickers/` с изображениями.
- Без фреймворков, без сборки, без CDN — страница должна открываться двойным
  кликом по файлу и работать офлайн.
- Данные стикеров — отдельный `stickers.json`, загружаемый `fetch`. Если открыть
  файл напрямую через `file://`, `fetch` может быть заблокирован браузером;
  предусмотреть запасной вариант — данные, встроенные в HTML, или запуск через
  простой локальный сервер. Решение зафиксировать в README.
- Формат изображений — WebP. Анимированные стикеры в Telegram приходят как
  `.tgs` (Lottie), браузер их не покажет без сторонней библиотеки; для сетки
  берём статические превью, анимацию добавляем только если отдельно попросят.
- Никакой аналитики, трекеров и внешних запросов, кроме ссылки на пак.

## Критерии готовности

- Открывается на телефоне, айберг читается без пинча и зума.
- Переключение всех трёх критериев меняет раскладку, а не только подписи.
- Карточка стикера открывается и закрывается всеми тремя способами.
- В коде нет ни одного выдуманного стикера: либо реальные данные из пака,
  либо явные заглушки с пометкой.
- Ссылка на репозиторий в README, если проект публикуется.

## Открытые вопросы

1. Оценки ставит исполнитель по своему прочтению или ты хочешь задать их сам?
   Это главный риск: субъективная разметка на 120 стикеров.
2. Нужна ли анимация на карточке или достаточно статики (стикеры статические,
   анимации нет в принципе).
3. Публиковать страницу на GitHub Pages или достаточно локального файла.
4. Что делать с репозиторием `aisberg-kurilki`: туда же класть страницу
   (сейчас там пусто и он публичный) или вести проект в папке `home-assistant`.
